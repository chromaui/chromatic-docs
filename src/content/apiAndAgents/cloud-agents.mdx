# Run Chromatic with cloud agents<BetaBadge />

Hand tasks to a coding agent and get back pull requests you can trust. In a software factory, a cloud agent picks up a ticket, writes the code, opens a pull request, and reads the Chromatic build to find out if the UI is right. It fixes what it can and leaves visual changes for a person to review.

![Cloud agent loop: an agent opens a pull request, Chromatic tests every build, the agent fixes what Chromatic finds, and a person reviews only the changes that need judgement](../../images/workflow-cloud-agents.png)

## Why software factories need Chromatic

A software factory only saves time if its work doesn't need redoing. For UI, that depends on whether the agent can see what it built. If it can't, a person has to check the UI, and more work gets rewritten. **Agents that can't see the UI are twice as likely to need a rewrite.**

| Agents                    | Typical UI change needs a rewrite |
| ------------------------- | --------------------------------- |
| Can't see the rendered UI | 19%                               |
| Can see the rendered UI   | 10%                               |

_Source: State of AI in Frontend Delivery 2026, a survey of 496 frontend engineers._

Chromatic lets the agent see the rendered UI and runs tests on it, then tells the agent what to act on: render failures, accessibility violations, and visual changes. The agent fixes the first two and checks each visual change against its code. Developers only review diffs that need human judgement.

## Set up

### 1. Connect your agent to Chromatic

There are two ways to connect:

| Connection                                        | Use when                                                                                  | Acts as                                           |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------- |
| [Chromatic MCP](#connect-using-the-chromatic-mcp) | Your agent platform supports remote MCP servers and someone can log in once               | The person who logged in                          |
| [Service client](#connect-using-a-service-client) | No one can log in through a browser, or you want access owned by the organization account | Your Chromatic organization account, not a person |

#### Connect using the Chromatic MCP

Add `https://mcp.chromatic.com/mcp` to your cloud agent's MCP settings ([Claude Desktop and claude.ai](/docs/mcp#claude-desktop), or [add the MCP server by hand](/docs/mcp#add-the-mcp-server-by-hand)), then log in once in your browser. After that, every session the agent runs can use the Chromatic tools without asking again.

**The agent acts as the person who logged in.** It has that person's access. It sees the projects that person can see, and anything it changes in Chromatic counts as that person's action. If that person leaves your Chromatic account, the agent loses access with them.

#### Connect using a service client

A service client lets an agent call the [Chromatic API](/docs/api) with no one logged in. It belongs to your Chromatic organization account, so it keeps working when people come and go.

1. [Create a service client](/docs/oauth-clients#create-a-service-client) with only the scopes the agent needs. To check builds, that's `project:read` and `build:read`.
2. Store the client ID and secret in your agent platform's secret manager. Never commit them.
3. Have the agent exchange them for an access token with the [client credentials flow](/docs/api#client-credentials-m2m), then query [`project`](/docs/api#project) and [`build`](/docs/api#build).

Tokens expire after 60 minutes and there's no refresh token, so the agent requests a new one when the current one expires.

### 2. Give cloud agents the skills

The skills call the Chromatic MCP tools, so this step applies when your agent connects through the MCP.

To give every cloud agent the skills, we recommend installing them in your repository with the skills CLI:

```shell
npx skills add chromaui/chromatic-plugins
```

Leave out `--global` so the skills go in the project, not your home folder. Commit them. Any agent that runs in the repository picks them up.

### 3. Tell your agent to respond to Chromatic

Add these instructions to `AGENTS.md` or your agent platform's equivalent:

```markdown
After you push, check the latest Chromatic build for this branch.

- Fix broken stories and new accessibility violations, push, and check the next build.
- Repeat until the build has no broken stories or new violations.
- List the remaining visual changes in the pull request for a person to review. Don't accept them.
- Mark the pull request ready only once the Chromatic build has finished. A passing CI job doesn't mean the UI passed.
- To test a UI change, add or update a story. Don't write a separate page-level test for the same thing.
```

See [Mandatory PR checks](/docs/mandatory-pr-checks#check-status-by-scenario) for what each build status means.

### 4. You only need to review what needs human judgement

The agent works through Chromatic's findings on its own. It fixes broken stories and accessibility violations, then uses the skills from step 2 to check whether each visual change matches the code on its branch.

You only step in when a change needs your call: is it an intended update or a regression? You review those few changes, not every snapshot.

![Claude Code reporting that 9 of 12 visual changes match the code change and 3 need a person to decide whether they're intended or regressions](../../images/cloud-agents-review-judgement.png)
