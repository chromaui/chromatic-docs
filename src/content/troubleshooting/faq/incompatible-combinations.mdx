# Flags that cannot be used together

Some Chromatic flags and configuration options are mutually exclusive or fundamentally incompatible.
Using them together either produces unexpected results, causes one to silently override the other, or makes one of them entirely irrelevant.
This article lists the known conflicting combinations and explains why each conflict occurs.

| **Flags & features**                                              | **Why they conflict?**                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **(onlyStoryNames or onlyStoryFiles) and onlyChanged(TurboSnap)** | TurboSnap is an automated smart filter — it uses your git history and dependency graph to decide which stories need to be tested. `onlyStoryNames` and `onlyStoryFiles` are manual filters — you explicitly tell Chromatic which stories or files to include, and Chromatic does not infer or validate those choices. |
| **onlyStoryNames and onlyStoryFiles**                             | Both options filter what gets tested, but when using them together only one gets applied.                                                                                                                                                                                                                             |
| **buildScriptName and storybookBuildDir**                         | These two options represent mutually exclusive approaches to providing a Storybook build to Chromatic.                                                                                                                                                                                                                |
| **autoAcceptChanges and exitZeroOnChanges**                       | Both flags prevent your CI pipeline from failing when visual changes are detected, but they do it differently: `autoAcceptChanges` automatically accepts all detected changes and `exitZeroOnChanges` exits with a zero status code without accepting changes.                                                        |
| **skip and any other flag**                                       | The `skip` flag bypasses the Chromatic build entirely, which invalidates any flag meant to tweak Chromatic's build behavior.                                                                                                                                                                                          |
| **forceRebuild and onlyChanged(TurboSnap)**                       | These flags have directly opposing goals. TurboSnap is meant to skip stories and `forceRebuild` is meant to test them all.                                                                                                                                                                                            |
| **cypress, playwright and vitest**                                | Mutually exclusive execution modes.                                                                                                                                                                                                                                                                                   |
