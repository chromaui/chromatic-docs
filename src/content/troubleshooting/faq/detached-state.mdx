# How do I fix a detached HEAD state?

A **detached HEAD state** means Git has checked out a commit instead of a branch. Chromatic may need explicit branch information to find the correct baseline.

## Most CI providers

Ephemeral merge commits or missing branch references can cause this in CI. Provide the Git context with [environment variables](/docs/faq/environment-variables). You must [set all three Git variables](/docs/cli#chromatic-git-options).

## GitHub

On GitHub Actions, this issue happens when:

- You are running on a `pull_request` event trigger
- You are missing the `ref` tag on the checkout step in CI when running on `pull_request`

## Local builds

Run `git status` to check whether `HEAD` is detached. This can happen after `git checkout <commit-hash>`, `git checkout origin/feature-branch`, or `gh pr checkout <number> --detach`. A regular `gh pr checkout <number>` creates or uses a local branch.

If you made a commit while detached and want to keep it on a branch, run `git switch -c <new-branch-name>`. Push the branch with `git push origin <new-branch-name>` if you need the commit on the remote.

If you haven't made commits while detached and want to work on an existing remote branch, use `git switch --track origin/feature-branch` to create a local tracking branch. If you already have a local branch, use `git switch feature-branch`.

## Check for an attached branch in CI

If your CI workflow requires an attached branch, check for one before running Chromatic:

```yaml
- name: Check for an attached branch
  run: git symbolic-ref -q HEAD >/dev/null
```

Some CI workflows intentionally check out a detached commit. In those workflows, provide the [Git environment variables](/docs/faq/environment-variables) instead of failing the build.
